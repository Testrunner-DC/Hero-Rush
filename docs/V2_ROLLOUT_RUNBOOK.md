# V2 对战灰度与回滚手册

规则基线：官方 1.02；引擎基线：`2.0.0-framework-rc1`。

## 前置门禁

生产开启前必须同时满足：`npm run gate:v2:release` 通过、完整效果卡池覆盖为 100%、双客户端部署冒烟通过、数据库 journal 可写且可重放。前端 `/battle` 已由 V2 大厅接管；`/battle-v2` 仅兼容跳转到 `/battle`。V1 对战代码与路由已经移除，不再作为回滚目标。

## 灰度顺序

1. 私人房：限定测试名单，至少运行 48 小时。
2. 休闲匹配：先 5%，稳定 24 小时后递增至 25%、50%、100%。
3. 排名匹配：休闲 100% 稳定 72 小时后，重复 5%、25%、50%、100% 阶梯。

每一阶至少满足：服务端 5xx 率低于 1%；非预期命令拒绝率低于 2%；断线恢复成功率不低于 99%；journal 写入失败为 0；重放哈希不一致为 0。任一指标越界即停止扩大。

## 回滚

先关闭服务端 `BATTLE_V2_ENABLED` 以暂停新对局，并保留 V2 journal 用于复盘，禁止通过删除对局数据回滚。V1 已移除，不允许切回旧权威引擎。若只有某个队列异常，优先下线排名，再下线休闲，最后下线好友房。恢复前必须重新通过框架门禁和双客户端冒烟。

## 开关约束

- `BATTLE_V2_ENABLED=false`
- `BATTLE_V2_ENFORCE_CARD_POOL=false`

服务端开关和卡池门禁的仓库默认值必须保持 `false`。生产环境如启用 V2，服务端必须同时要求 `BATTLE_V2_ENFORCE_CARD_POOL=true`，否则启动直接失败。
