## 3. 单方组件布局

单方战场实现为可复用的 `PlayerBoardV2`，不把两个玩家和业务操作继续堆在一个巨型页面组件中。

```text
┌────────┬───────────────────────────────┬────────┐
│ 时间线 │      左侧翼  先锋  右侧翼     │ 虚空区 │
│        │              后卫             ├────────┤
│        │                               │ 撤退区 │
├────────┼───────────────────────────────┼────────┤
│冲击卡组│             基地区            │ 主卡组 │
└────────┴───────────────────────────────┴────────┘
│                    手牌                         │
└─────────────────────────────────────────────────┘
```

约束：

- 先锋、两侧翼、后卫必须保持示意图中的菱形空间关系，不能为了适配宽度改成四个无语义的并排格子。
- 基地区属于场上，但视觉上与四个战区分层；手牌不属于场上，必须位于战场容器之外。
- 敌方区域可为朝向战场中央而镜像排列，但不旋转卡面和文字，也不改变 `flankLeft`、`flankRight` 的语义字段。
- 所有区域以 `instanceId` 定位卡牌；前端不能继续用 `handIndex` 生成网络命令。
- 点击区域只提交 V2 允许命令；阶段推进、抽卡、洗牌和合法目标均由服务端决定。

## 4. 双方页面组合

- 桌面端：敌方 `PlayerBoardV2` 在上、己方在下，中间保留流程/优先权提示带；公共日志和卡牌详情放在可折叠侧栏。
- 当前行动方只通过边框、区域光效和文字提示强调，不改变区域位置，避免玩家在回合切换时重新寻找卡位。
- 待处理决策使用固定提示层；调度、目标选择和排序均由 `pendingDecision` 渲染，不能通过读取旧引擎内部字段猜测。
- 对手隐藏区永远从 `BattleViewV2` 的计数渲染，不能让浏览器先收到实体卡再用 CSS 隐藏。

## 5. 响应式约束

- 宽屏：完整显示两侧的时间线、冲击卡组、虚空区、撤退区和主卡组。
- 中屏：侧区压缩为窄牌堆与数量徽标；四战区和基地区的相对关系保持不变。
- 小屏：一次重点显示一个玩家战场，另一方缩为状态条；侧区进入抽屉，但关键数量、行动方和待处理决策必须常驻。
- 不允许通过无限缩小卡牌解决空间不足；优先滚动手牌、折叠日志和详情面板。

## 6. 与现有页面的迁移关系

- 现有 `PlayerArea.tsx` 已具有四战区的基本菱形排列，可保留区域卡牌渲染经验。
- 现有 `BattlePage.tsx` 同时承担旧状态解释、命令拼装、提示层和整页布局；V2 接入时拆成页面编排、单方战场、决策面板和只读侧栏。
- 先为 V2 新建组件，不直接重写旧线上组件；完成 `MatchRoomV2`、重连和调度链路后再通过功能开关切换。
