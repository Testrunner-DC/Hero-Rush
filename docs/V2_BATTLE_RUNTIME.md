# V2 对战运行结构

Hero-Rush 的“对战”入口默认进入 V2 大厅，旧框架仅保留在 `/battle-legacy` 供问题回溯。

## 用户入口

- `/battle`：V2 对战大厅，包含休闲匹配、好友房和测试沙盒入口。
- `/battle/sandbox`：固定种子、本地双人牌组的规则沙盒；复用 V2 权威内核，不写入正式对战记录。
- `/admin`：最小化管理后台，只显示 V2 服务、匹配队列、房间、原子操作、效果注册和严格卡池状态。

## 服务端接口

- `GET /api/health`：公开健康状态，不返回秘密。
- `POST /api/admin/login`：管理员登录，带频率限制。
- `GET /api/admin/overview`：Bearer 会话鉴权后的 V2 运维概览。
- `POST /api/admin/logout`：注销当前内存会话。

管理员密码不进入仓库。开发机使用被 Git 忽略的 `server/.env.local`，部署环境使用宿主机环境变量，并只提供 `ADMIN_PASSWORD_SCRYPT`。管理会话为随机、不透明、进程内令牌，服务重启后失效。

## 卡牌效果原子化

当前原子目录包含抽牌、撤退、移动场上卡牌、添加/移除修正、附着/解除附着七类操作。执行器为每个原子生成验证结果、事件类型与终局状态追踪；效果注册表只向后台暴露可序列化描述，不暴露执行回调。

原子机制已经可用，但“机制完成”不等于“全卡牌效果完成”。正式卡牌必须逐张注册实现，并通过严格卡池覆盖门禁后，才允许进入生产对战。

## 存储边界

沙盒、管理会话和匹配状态均为运行态数据，不产生新的仓库资产。构建验收完成后运行 `npm run clean:generated` 清理可再生产物，再运行 `npm run storage:audit -- -Strict` 验证预算。
